# Evidence-organized scientific workflow

This upgrade extends the existing TypeScript laboratory with a Research Learning
Engine, a reconstructible Scientific Knowledge Graph and a generalized experiment
compiler. James, Jasmine, Luca and Elena retain their roles. Local Qwen remains
behind the existing LM Studio adapter. The journal, native registry, host
validation and operator authority remain the persistence and execution boundaries.

## Public investigation and original implementation

The installed [REA framework](https://github.com/morluto/rea) and its connected MCP
server inspected three public websites in a dedicated browser profile on Windows.
CDP access was restricted to loopback and the four explicitly allowed public
origins, including Mirrors' redirect. Passive page inspection, accessibility text,
static JavaScript bundle/module analysis and limited public UI observation worked.
No authenticated product backend, source maps or hidden compiler implementation
was established. No native target was available or needed. Ordinary source
inspection was used for R.A.I.N.'s own repository.

The reports distinguish observation, public documentation, supported inference and
unknown implementation. [Mirrors](rea-research/mirrors/observations.md) motivated
trace-grounded contextual guidance; [Poth Labs](rea-research/poth-labs/observations.md)
motivated inspectable links between evidence and competing explanations;
[Infera](rea-research/infera/observations.md) motivated explicit preflight and
execution-readiness stages. Poth's current public product concerns customer
evidence, rather than a demonstrated general scientific graph. These are
behavioral inspirations, not reproductions of proprietary implementations.

See the [capability matrix](rea-research/capability-matrix.md) and each application's
implementation requirements for the original acceptance specifications. Private
REA bundles containing captured public script bytes remain outside the repository.
Only source locations, hashes, evidence identifiers, bounded coverage metadata and
our own findings are published. No extracted implementation was copied.

## One research cycle

The graph projects approved corpus receipts and the hash-chained discovery journal.
Researchers retrieve those source-context links, competing hypotheses and approved
procedural guidance. The existing Bethesda compiler or numerical compiler
deterministically validates a typed design and preregisters it. A scoped,
digest-bound operator authorization precedes execution. Independent replay and
the native registry admit simulator measurements. The graph then reconstructs
measurement lineage; the learning engine examines procedural validation receipts
and proposes improvements for independent evaluation.

The new components communicate through data-only types in `src/bethesda/rain/`.
Server implementations live in `src/rain/research/`, `src/rain/scientific/` and the
existing autonomy service. The browser cannot import filesystem, model or simulator
authority. Local service actions retain the existing loopback/origin checks,
closed request keys, bounded bodies, write budgets and shared execution lock.

## Learning and scientific standing

The [learning engine](RAIN_RESEARCH_LEARNING.md) recognizes repeated deterministic
proposal errors in distinct retained receipts. Scientifically valid negative
results are not procedural failures. Guidance has immutable versions, scoped
matching, independent frozen held-out evaluations, explicit approval and rollback.
No evaluation rule can be replaced after outcomes are available. The same native
compiler scores baseline and candidate answers; retained raw answers can be
independently rescored. Approval checks the full beneficial evaluation digest.
An evaluated proposal remains inactive until reviewed by an operator.

The graph has stable provenance-linked paper, equation, hypothesis, assumption,
question, protocol, measurement, contradiction, missing-evidence, falsification and
limitation nodes. Typed edges preserve separate source-context, model-suggested,
operator-assessed, host-observed and verified-simulator standing. Lexical assumption
and equation extraction is inspectable manuscript context, not independent
scientific verification. A manuscript with no explicitly linked admitted test
produces an unresolved test question with the source's hash and line locator.
Absence in this registry means missing evidence here, not proof that nobody has
tested it elsewhere. Explicit hypothesis-test links avoid treating a thematically
related simulation as verification of a paper. Verified numerical measurements
require a replay receipt and matching registry admission. The graph is a derived
view and can be rebuilt; it cannot overrule authoritative records.

## Compiler and real backends

The versioned intermediate representation records scientific intent, quantities
and SI units, independent/dependent variables, controls, constraints, resources,
analysis, falsification and provenance. Bethesda delegates to its existing design
compiler, charter checks, runner and replay. Its execution authority is unchanged.

The numerical backend implements a bounded linear underdamped driven oscillator:
`m x'' + b x' + k x = F cos(omega t)`. Treatment and a zero-force control share
initial conditions. RK4 integration is checked against an independently expressed
closed-form solution for both position and velocity. Host validation rejects
wrong units, nonfinite data, unsupported damping regimes, excessive budgets,
unstable timesteps, insufficient sampling and invalid evidence references.
Analysis and reference tolerances are sealed before execution. Failures and
interruptions retain their state. Numerical authorization has its own simulation
scope and expiry; Bethesda authority never implicitly covers it.

Reference agreement and byte-deterministic same-runtime replay establish numerical
correctness under the specified model, not physical validation. Cross-engine
floating-point identity is not guaranteed. No physical equipment, DRR or TRIAD
backend is enabled. Capability panels show these limitations.

## Workbench and demonstrations

Enter the existing Bethesda R.A.I.N. discovery workbench to inspect learning
history, baseline/candidate metrics and intervals, graph queries, contradictions,
missing evidence, provenance, experiment IR, backend capabilities, approvals and
experimental lineage. Graph search and inspection are read-only. Qwen drafting,
compile/preregister, reviewed authorization and execution are separate controls.
The editable human example and actual model draft retain distinct authorship.

```sh
# Integration fixture: explicitly scripted approval, actual numerical simulation
bun run rain:scientific:demo --dir .rain-research/my-fixture
# Ask local Qwen; no execution occurs
bun run rain:scientific:draft
# After reviewing the complete plan, explicitly authorize its exact digest
bun run rain:scientific --execute-reviewed <full-plan-sha256>
# Frozen baseline/candidate Qwen pilot; guidance stays inactive
bun run rain:learning:live --tasks 4
# Independently validate the retained public demonstration artifacts
bun run rain:scientific:verify
```

Scripted demonstrations cannot stand in for human approval of a live experiment.
Live execution requires a separate operator review of its actual plan. Failed and
incomplete local model calls remain in the journal. Public evidence exports contain
only our original outputs; review them before using `--publish-dir`.

## Evaluation interpretation

The [scripted integration evidence](rea-research/evaluations/scripted/demonstration.json)
contains eight frozen held-out compiler tasks, distinct from the two training
refusals. Both arms use the same questions, evidence and budgets. Baseline preserves
the invalid scripted proposal; candidate applies the proposed grid guidance.
Compilation and the composite valid-proposal rate improve from 0/8 to 8/8.
Wilson 95% intervals are [0, 0.324] and [0.676, 1]; the paired exact sign calculation
is 0.0078125. The fixtures deliberately exercise that error class; exchangeability
and representative population sampling have not been established.

Evidence references, contradiction identification and unsupported-claim detection
remain 8/8 in both scripted arms. Those synthetic labels exercise scoring, not
real-world scientific judgment. Definition repeatability is a compilation metric;
the separately executed oscillator supplies actual simulation replay evidence.
Question coverage and selection use a frozen primary-metric proxy and do not
establish optimal experiment choice. Each arm uses eight participant calls; each
primary scoring pass makes 32 compiler calls across both arms, with no simulator
actor ticks. Independent rescoring adds another pass, and derived-view verification
can add further passes; those verification costs are excluded from the resource
field. Scripted token use is unknown (`null`).

The original oscillator integration run completes two arms with 2,000 integration
steps and 202 retained samples. Its RMS treatment/control difference is
0.5373464823217641 m, maximum position reference error 8.020637265460095e-9 m and
maximum velocity reference error 1.515128256190934e-8 m/s. These are actual
simulator outputs, retained in the journal with preregistration, independent replay
and registry receipts. The run records its real producing Git revision and dirty
worktree status. It does not validate the corpus's physical research claims.

The integrated tests cover rejection, tampering, stale authority, held-out
contamination, negative outcomes, numerical convergence, registry admission,
graph reconstruction, service locking and browser authority boundaries. More
activity, longer traces or additional papers are not reported as intelligence gains.
Broader scientific improvement requires independently sampled tasks and more live
observations than this targeted procedural demonstration.
