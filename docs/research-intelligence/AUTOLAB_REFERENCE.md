# Autolab architectural reference — 2026-11-13

This is a dated public-source investigation, using Reverse Engineer Anything (REA) for browser observations and ordinary source tools for open-source repositories. It informs R.A.I.N. design; it does not establish a measured performance comparison with Autolab.

## Scope and evidence standard

**Documented** means a first-party page or public contract describes the behavior. **Observed** means it occurred in the anonymous browser or a public read during this investigation. **Source-confirmed** means the named public implementation contains the mechanism; it does not prove the hosted service deploys that revision. **Proposed** identifies a R.A.I.N. design choice. An unobserved capability remains unknown, rather than absent.

Only the public website, documentation, anonymous Explore page, documented health/OpenAPI GETs, and public GitHub repositories were accessed. No account login, authenticated experiment, rental, payment, machine attachment, private service, or platform installation was attempted. Existing research evidence was preserved. The fresh observation browser was closed after capture.

The [evidence manifest](autolab-evidence/manifest.json) records full Evidence IDs, capture windows, scope filters, limitations, public repository revisions, and SHA-256 digests of locally retained raw files. Raw records and the isolated browser profile are ignored to avoid publishing public profile content or incidental local details. The tracked manifest is an excerpt, not a complete REA evidence bundle.

## Evaluation and continuous-learning limits

Autolab's [benchmark-methodology article](https://www.autolab.ai/research/blog-1-how-to-pick-the-best-model/) documents repeated independent loops, run isolation, fixed resource budgets, and reporting variability. It describes discarding contaminated runs that shared agent memory. Its [running comparison](https://www.autolab.ai/research/best-model/) reports seven runs per model/task for most models and provides raw-trajectory links. These are first-party reported benchmark procedures; neither the numerical findings nor automated enforcement of those procedures in ordinary climbs was independently reproduced here.

No authenticated experiment was run, so scheduler throughput, recovery guarantees, budget enforcement, protected-data isolation, and research-quality improvements remain experimentally unverified. The reviewed pages and source files did not establish automatic multiplicity correction, mandatory independent replication, calibrated scientific uncertainty, causal identifiability checks, or evaluator-independent peer-review vetoes. This is a bounded search result, not a claim that Autolab lacks those capabilities.

## Original design implications for R.A.I.N.

These are **proposed R.A.I.N. mechanisms**, justified by scientific requirements and the local architecture investigation; they are not reconstructed proprietary Autolab internals:

1. Treat a scientific claim as a versioned object with a prediction, falsifier, baseline, metric direction, minimum meaningful effect, and stopping/replication policy registered before measurement. Tie conclusions to evidence rather than agent confidence.
2. Separate exploratory selection from confirmation. Reserve disjoint seeds or conditions and budget for replication; retain every tested alternative so selective reporting and repeated comparisons remain visible.
3. Distinguish contradicted predictions, inconclusive estimates, invalid measurements, and infrastructure failures. Only an interpretable measurement should update belief about a hypothesis.
4. Schedule discrimination between competing explanations per measured cost. Report information-value estimates as estimates, then evaluate whether the chosen experiment actually reduced uncertainty.
5. Preserve agent identities and human memories while adding an append-only research ledger linking hypotheses, attempts, evaluator/code/data hashes, seeds, artifacts, critiques, and method decisions. Summaries should reference evidence they compress.
6. Evaluate proposed method changes on fixed suites and fresh confirmation conditions. Keep changes reversible; promotion beyond authorized boundaries remains a human decision.

The acceptance test is whether R.A.I.N. rejects false improvements, selects informative experiments, reproduces effects, and explains failure under controlled conditions. More agents, more runs, or richer UI alone cannot satisfy that test. This investigation supplies engineering references and observable evidence; it makes no claim that R.A.I.N. has surpassed Autolab.

## Reproduction notes

With an already installed Playwright and Chromium, set `PLAYWRIGHT_MODULE` to the local module location if it cannot be resolved normally, then run `node docs/research-intelligence/autolab-evidence/public-browser.cjs`. The helper opens only the three public origins and exposes the owned browser on loopback port 9341; no service is installed. Use `--codex-tab` for the public-tab action and `--close` to close the owned browser. REA `list_browser_targets` selects the current IDs; `inspect_web_page` with the manifest's flags creates fresh evidence. Dynamic pages and IDs can change. Export new raw files under unique names; never overwrite earlier evidence.

All seven original questions are answered to different depths: public architecture and evaluation format are documented/source-confirmed; public frontend rendering is observed; hosted coordination, scheduling, optimization quality, and long-term learning are only partially answered. Their remaining gaps require authenticated, explicitly scoped experiments and cannot be filled by inference from marketing pages.
